## 流程总览

```
① 采集        collect_images.py      爬 400~600 张候选图      ~15 分钟
② 清洗去重    supplement.py 的去重逻辑  md5 + pHash 剔除重复   ~10 分钟
③ AI 预标注   auto_label.py          YOLO-World 打初版框      ~10 分钟
④ 人工复核    X-AnyLabeling          改框/补框/删水印图        2~4 小时（唯一的人工环节）
⑤ 标注回写    xlabel_bridge.py       JSON → YOLO txt           ~10 秒
⑥ 合并重框    merge_boxes.py         一图一框                  ~5 秒
⑦ 划分        split_dataset.py       8:1:1 + 生成 data.yaml    ~10 秒
⑧ 三重质检    check_dataset / qc_labels  挡住 80% 的坑         ~30 秒
⑨ 训练        train.py               100 epochs               ~22 分钟
⑩ 评估        eval_compare.py        test / val 双集            ~20 秒
⑪ 推理        predict_image / video  图像 + 视频               ~1 分钟
```

**时间分布的关键事实**：训练只占 22 分钟，**人工复核占 2~4 小时**。想省时间要省在标注上（AI 预标注能覆盖 60~90% 的框），而不是省训练轮数。

# 第一部分：数据准备

## 1.1 环境确认（一次性）

```bash
python -c "import ultralytics, torch; print(ultralytics.__version__, torch.__version__)"
# 期望输出：8.4.185 2.14.1+cpu
```

缺依赖就装：

```bash
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

> **本机重装注意**：`pip install ultralytics` 默认会拉 3GB 的 CUDA 版 torch，必须先装 CPU 版 torch 再装 ultralytics。

## 1.2 采集图片

改 `src/data_prep/collect_images.py` 顶部的 `CLASSES` 字典（类别名 → 搜索关键词列表），然后：

```bash
python src/data_prep/collect_images.py
```

- 输出目录：`data/data_raw/<类别名>/000001.jpg...`
- 每个关键词爬 40 张（`MAX_PER_QUERY`），每类给 2~3 组关键词，5 类约 400~600 张
- 关键词越具体越好：`长城 慕田峪` 比 `长城` 干净；中英文各来一组能显著提升多样性

> 也可以手工找图：把图片按类放进 `data/data_raw/<类别名>/`，效果一样。

## 1.3 清洗去重

爬虫结果必然混入重复图、水印图、无关图。去重逻辑（md5 完全重复 + pHash 近重复）已经封装在 `src/data_prep/supplement.py` 里，直接用它跑一遍补充流程即可自动剔除；也可以手工肉眼过一遍，删掉：

- 带明显水印的（小红书、知乎、Stock 图库）
- 截图、海报、拼贴图（一张图里塞多栋建筑）
- 与类别无关的（搜"长城"出来的长城汽车、长城葡萄酒）

> 水印图务必在**标注前**删掉。标注完再删会导致标注文件和图片对不上。

## 1.4 AI 预标注（省 60~90% 的框选工作）

```bash
python src/data_prep/auto_label.py --conf 0.15 --imgsz 640
```

- 用 YOLO-World 开放词表模型，**不需要训练就能出框**
- 首次运行自动下载 `yolov8s-worldv2.pt`（25MB）+ CLIP 编码器（338MB）到项目目录，需要能访问 GitHub
- 输出：
  - `data/labeled/images/<类别>_000001.jpg`（图片全部拷过来）
  - `data/labeled/labels/<类别>_000001.txt`（YOLO 初版标注，未检出的写空文件）
  - `data/labeled/_needs_manual.txt`（没检出目标的图清单，需要重点补框）

> `--conf 0.15` 宜低不宜高：低了只是多几个错框（人工删掉即可），高了会漏框（人工要重画）。

## 1.5 人工复核（唯一必须人工的环节）

**第一步，转成 X-AnyLabeling 能读的格式**（它只认自己的 `.json`，不读 YOLO `.txt`）：

```bash
python src/data_prep/xlabel_bridge.py to_json
```

**第二步，打开软件复核**：

1. 启动 X-AnyLabeling（桌面有快捷方式）
2. 文件 → 打开目录 → 选 `data/labeled/images/`
3. 有框的图会显示红框；标题显示 `[未标注]` 的就是需要补框的
4. 逐张检查，做四件事：
   - **删错框**：框到别的建筑上的（比如把纪念碑框成天安门）
   - **补漏框**：主要目标没框上的
   - **合并重复框**：同一栋建筑被框了 2~3 次 → 只留一个（这一步也可以交给 `merge_boxes.py` 自动做）
   - **删水印图**：图片和同名 `.json` 一起删
5. **Ctrl+S 保存**（务必存回同一目录）

**第三步，转回训练格式**：

```bash
python src/data_prep/xlabel_bridge.py to_yolo
```

会覆盖 `data/labeled/labels/*.txt`，并打印每个类别的框数。

> 回环安全性：`to_json` 和 `to_yolo` 已做过 512 框守恒验证，来回转换不丢框（但会丢"多边形"信息，只保留外接矩形）。

## 1.6 合并同类重叠框

```bash
python src/data_prep/merge_boxes.py --dry-run   # 先看会合并多少
python src/data_prep/merge_boxes.py             # 执行
```

规则：同类别内 IoU > 0.2 或包含度 > 0.7 的框归为一簇，取外接框。

**为什么必须做**：地标是单实例目标（一栋建筑一个框）。多个重叠 GT 会让模型学成"一个目标输出多个框"，推理时出现重复检测，同时拉低 mAP。本项目实测：合并后 539 框 → 361 框，test mAP50 从 0.728 提到 0.817。

# 第二部分：标注完成后的训练步骤（重点）

> 这一节假设你已经完成 1.5 的人工复核，`data/labeled/images/` 和 `labels/` 都是最终版。

## 步骤 1：确认标注已回写为 YOLO 格式

```bash
python src/data_prep/xlabel_bridge.py to_yolo
```

期望输出类似：

```
[to_yolo] 处理 329 个 JSON -> YOLO txt
  总框数 335；空标注 0 张
  各类框数: {'eiffel_tower': 50, 'sydney_opera': 63, ...}
```

**如果"空标注"数量很大**（>10%），说明有大量图没框，回去补；或者这些图本来就该删。

## 步骤 2：划分训练/验证/测试集

```bash
python src/data_prep/split_dataset.py
```

内部做三件事：

1. 扫描 `data/labeled/images/`，只收"图片 + 同名 txt"都存在的配对
2. 按 8:1:1、`seed=42` 随机打乱后复制到 `data/dataset/{images,labels}/{train,val,test}/`
3. 生成 `data.yaml`（绝对路径 + 5 个类别名）

期望输出：

```
train:  263 张
val  :   32 张
test :   34 张
总计 329 对 (图片+标注)，已生成 data.yaml，类别 5 个: [...]
```

> **重要**：`split_dataset.py` 只复制不清理。如果之前划分过、图片集合变了，旧文件会残留。重跑前先清空 `data/dataset/`（或先跑 `qc_labels.py` 看"dataset 多出"是否为 0）。

## 步骤 3：三重质检（这一步不能跳）

```bash
# ① 基础：配对、坐标越界、空标注、类别 id 越界
python src/data_prep/check_dataset.py --nc 5

# ② 深度：文件名类别与标注类别是否一致、同类重复框、极小框、dataset 与 labeled 是否同步
python src/data_prep/qc_labels.py
```

**`--nc 5` 必须与 `data/classes.txt` 的类别数一致**，写错会误报"类别 id 越界"。

合格标准（本次项目实测值，可作参照）：

| 检查项 | 合格 | 危险信号 |
|---|---|---|
| 图片与标注配对 | 100% | 有缺失 → 训练会跳过该图 |
| 空标注 | 0 | 大量空标注会拉低召回 |
| 类别 id 越界 | 0 | 训练直接报错 |
| 文件名类别 vs 标注类别不一致 | 0 | 说明框对了但类别选错，模型会学乱 |
| 同类重复框 | 0 | 一图多框 → 推理重复检测 |
| dataset 与 labeled 差异 | 0 / 0 | 不为 0 说明 split 过期，重跑步骤 2 |

**两条命令都必须打印"通过"才能进训练。** `qc_labels.py` 会直接告诉你"结构性检查通过"。

## 步骤 4：训练

```bash
python src/train_eval/train.py
```

默认配置（就是本项目的交付配置）：

| 参数 | 值 | 为什么这么设 |
|---|---|---|
| model | yolo11n | 260 万参数，CPU 上最快的 YOLO11 |
| imgsz | 320 | 像素量是 640 的 1/4，训练快 4 倍；建筑是大目标，够了 |
| batch | 16 | 29GB 内存完全撑得住 |
| freeze | 10 | 冻结 backbone，提速约 1/3，小数据集精度损失很小 |
| epochs | 100 | 配 `cos_lr=True` 必须跑满 |
| patience | 100 | 与 epochs 相同，避免早停打断余弦退火 |
| workers | 0 | Windows 下多进程 dataloader 易卡死 |
| cache | ram | 300 张图解码后仅 0.1GB，常驻内存 |

**耗时预期**：约 13~14 秒/epoch × 100 ≈ **22 分钟**（Ryzen 7 7840H 8C16T 全核）。

训练过程中的输出长这样：

```
      Epoch    GPU_mem   box_loss   cls_loss   dfl_loss  Instances       Size
      1/100         0G      1.443      3.893      1.517         40        320: 100% 17/17 14.2s
                 Class     Images  Instances      Box(P          R      mAP50  mAP50-95)
                   all         32         33      0.412      0.716       0.57      0.308
```

**怎么看是否正常**：

- `box_loss` / `cls_loss` / `dfl_loss` 三个损失应该**整体下降**（允许抖动）
- `mAP50` 应在前 10 轮内快速爬到 0.7 以上（迁移学习的红利）
- 如果 20 轮后 mAP50 还在 0.3 以下 → 数据或标注有问题，别硬等，停下来查

训练结束会自动在 test 集评估，最后打印：

```
[test] mAP@50=0.869  mAP@50-95=0.532
权重位置: runs/detect/<name>/weights/best.pt
```

**产物位置**：`runs/detect/<name>/`（`name` 默认 `landmark_yolo11n`，可用 `--name` 改）

| 文件 | 用途 |
|---|---|
| `weights/best.pt` | **最佳权重**，推理就用它 |
| `weights/last.pt` | 最后一轮权重 |
| `results.csv` | 逐轮指标，找最佳 epoch |
| `results.png` | loss 与 mAP 曲线 |
| `confusion_matrix.png` | 哪两类互相混淆 |
| `BoxPR_curve.png` / `BoxF1_curve.png` | PR、F1 曲线 |

> **改实验名养成习惯**：`--name exp_v2`。默认名会覆盖上一次结果（`exist_ok=True`），历史对比就没了。

## 步骤 5：评估

```bash
# 在独立测试集上评估（最重要）
python src/train_eval/eval_compare.py --weights runs/detect/<name>/weights/best.pt --split test

# 在验证集上交叉验证（判断 test 上的差异是不是小样本波动）
python src/train_eval/eval_compare.py --weights runs/detect/<name>/weights/best.pt --split val
```

输出是 Markdown 表格，可以直接贴进报告：

```
| 类别 | mAP50 / mAP50-95 |
|---|---|
| **全部** | 0.869 / 0.532 |
| eiffel_tower | 0.995 / 0.694 |
| ...
```

也可以一次对比多个模型：

```bash
python src/train_eval/eval_compare.py \
    --weights models/best.pt runs/detect/exp_480/weights/best.pt \
    --split test
```

### 怎么判断"能不能用"

| 指标 | 含义 | 参考线 |
|---|---|---|
| mAP@50 | 框重叠 50% 就算对 → 衡量"能不能找到" | ≥0.80 可用于演示 |
| mAP@50-95 | 多个 IoU 阈值平均 → 衡量"框得准不准" | ≥0.50 算良好 |
| 逐类 AP50 | 找短板 | 某一类明显低 → 该类数据不足或标法不一致 |

**必须警惕的两件事**：

1. **test 集太小会让单类指标剧烈波动**。本项目 test 只有 34 张，自由女神仅 4 张——一张判错就掉 25 个百分点。所以要看 **test + val 双集**：两集都低才是真短板，只在一集低多半是波动。
2. **评估分辨率必须与训练分辨率一致**。拿 480 训练的模型按 320 评估，会得到虚高的数字（实测 0.896 vs 真实 0.919 的差别被抹平）。

## 步骤 6：启用新模型 + 推理验证

```bash
# 新模型替换为默认模型
cp runs/detect/<name>/weights/best.pt models/best.pt

# 单图验证
python src/inference/predict_image.py --source data/demo_imgs/ --save --conf 0.25

# 视频验证
python src/inference/predict_video.py --source data/demo.mp4
```

图像结果：`runs/detect/predict/`（加 `--save` 才有）
视频结果：`runs/video/result.mp4`

**验证清单**（不只看类别对不对）：

- 框有没有明显偏移、框住背景一大片
- 同一目标有没有重复出框（说明标注里还有多框）
- 换个角度/天气的图还能不能认（检验泛化）
- 视频里框是否稳定（单帧检测没有时序平滑，轻微抖动属正常）

# 第三部分：常见问题对照表

| 现象 | 根因 | 解决 |
|---|---|---|
| `找不到权重文件` | models/best.pt 不存在且 runs 下没有 best.pt | 先训练，或 `--weights` 指定路径 |
| `数据集找不到 / path 不对` | data.yaml 里 path 是绝对路径，被移动过 | 重跑 `split_dataset.py` 重新生成 |
| `类别 id 越界` | classes.txt 类别数与标注 id 不匹配（增删类导致位移） | 改完 classes.txt 必须重跑 `xlabel_bridge.py to_yolo` 重建全部标签 |
| 训练 loss 不降 | 标注错位、类别错标、学习率过大 | 跑 `qc_labels.py`；看 `train_batch0.jpg` 里框和物体是否对齐 |
| mAP50 高但 mAP50-95 低 | 框不贴身（大目标常见） | 补数据；或标注改为"框主体"而非整片 |
| 推理出现多个重叠框 | 训练集一图多框 | 跑 `merge_boxes.py` 后重训 |
| 某一类 AP 特别低 | 该类样本少 / 类内形态差异大 | 优先补这一类数据 |
| `CUDA out of memory` | 误装了 GPU 版 torch 或 batch 太大 | 装 CPU 版 torch；降 `--batch` |
| 训练卡在第一个 epoch 不动 | Windows 下 `workers>0` | 保持 `--workers 0` |
| 中文路径报错 | OpenCV 编解码问题 | 本项目已验证中文路径可用；自建项目建议用英文路径 |
